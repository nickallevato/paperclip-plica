# Plica 0.6.0

The first release Plica cut itself. Nothing in the plugin changed.

## Nothing to do

There is no user-facing change in this version — no new screen, no moved
control, no behaviour difference. If you are running 0.5.0 and it is doing what
you want, there is no reason to upgrade today; the next feature release will
carry one.

What changed is how a version reaches you. 0.5.0 was published by hand. This
one was published by pushing a tag, and every release after it will be.

## Pushing a tag is the release

`v0.6.0` on `main` starts the
[`release` workflow](../../.github/workflows/release.yml), which installs
against the pinned Paperclip core the way CI does and publishes
`paperclip-plugin-plica` to npm.

A publish is the one thing this repository does that cannot be undone: npm never
lets a version be reused, so a bad release is fixed by the next one and never by
republishing. So there is exactly one script that reaches the registry
(`scripts/publish-npm.mjs`), and the workflow, a person at a terminal
(`pnpm release:publish`) and an agent on a release task all run it — there is no
second, luckier path. It refuses:

- a tag that disagrees with `package.json`,
- a `src/manifest.ts` left on the previous version, which the host would report
  in `plugin list` while `pnpm install` reported the other number,
- a version with no changelog entry or release page,
- an unclean checkout, since the tarball is packed from the working tree and an
  uncommitted edit would ship unrecorded.

`pnpm check:release` runs those version checks on their own, before there is a
tag to push. `prepublishOnly` typechecks, builds and tests inside
`npm publish`, so a red tree cannot reach the registry.

Credentials never enter the repository. A token comes off the environment and
goes into a private npm config that is deleted before the script exits, and the
script prints which variable it used — after a release nobody expected, "which
credential published this" is the first question. Trusted publishing over
GitHub Actions OIDC needs no token at all and is the preferred setup. See
[docs/releases/README.md](README.md#publishing-credentials).

## For maintainers

The steps for cutting the next one are in
[docs/releases/README.md](README.md#cutting-a-release). The rehearsal is worth
knowing: **Actions → release → Run workflow** with **dry run** left checked
packs the tarball, runs every check, and publishes nothing.

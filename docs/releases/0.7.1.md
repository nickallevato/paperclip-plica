# Tickler 0.7.1

One fix: the board's left column is no longer cut off at the bottom.

## What was wrong

The left column is pinned (`position: sticky`) inside Paperclip's scrolling
`<main>`, which starts below the host's top bar and breadcrumb and is therefore
always shorter than the window. The column was capped at the window's height, so
it was taller than the box it is pinned in: its last panels were painted below
the edge of the scroll area, and because the column is pinned nothing could
scroll down to them. The only thing that appeared to move the column was
scrolling the queue on the right.

On a 1600×900 window the cap came out 28px taller than the scroller, Portfolio
was squeezed to a bare heading and legend with no rows, and 146px of Routines
sat below the edge, unreachable.

## What changed

- The cap is measured from the box the column is actually pinned inside, and
  re-measured on resize and on entering or leaving kiosk mode. CSS keeps the
  viewport-based value as the first-paint fallback.
- The column scrolls itself when its fixed-height panels alone still exceed the
  cap — a long Orgs list, for example. Scroll chaining stays on, so the wheel
  carries on down the page at the end of the column.
- Portfolio keeps a minimum height instead of being squeezed to a heading.

Nothing changes below 64rem, where the column is laid out inline and the window
scrolls. On a window with room to spare the change is inert.

## What you have to do

Upgrade. There is no setting to change and nothing to migrate.

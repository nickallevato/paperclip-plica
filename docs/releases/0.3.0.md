# Plica 0.3.0

The release that made the page demonstrable, and stopped the rails from moving
under you.

## Demo mode

Plica can now serve the entire HUD — every read *and* every write — from a
bundled fixture instead of your instance.

Four invented companies, ~40 tickets, ~22 agents, live runs, approvals, an
overdue routine and a company in the red. Enough that every surface has
something to draw rather than reading as an empty prototype. Approvals can be
approved and questions answered during a walkthrough, and none of it reaches the
server.

Two switches: `?demo=1` on the URL, sticky for the browser session; and a **Demo
mode** checkbox on the plugin's settings page, which Paperclip generates from
the manifest. Host plugin config is per company and Plica is not, so ticking it
for any one company turns the whole page into a demo.

It fails closed — if the fixture cannot be loaded, Plica shows an error rather
than quietly falling back to real data — and an orange **DEMO DATA** badge sits
in the header the entire time it is on.

See [Configuration → Demo mode](../configuration.md#demo-mode).

## Live moved out of the rail

Running agents are now a single row of pills across the top of the board rather
than a list down the side.

Live was the one block whose height tracked the size of the fleet, so every run
that started or finished shoved everything below it down the page. As a fixed
row its height cannot change and nothing below it ever moves. Titles and agent
narration went into the hover card, where they cannot wrap a pill onto a second
line. There is no cap and no "+N more": the row scrolls sideways, so the header
count and what you can reach always agree.

## Portfolio is a chart

The projects rail is now one worst-first chart across every company, each bar
split into moving / waiting / blocked. What people actually read off the old
list was the shape of the work, so it became the shape of the work. The folds,
the company grouping and the sort controls went with it.

## Routines show exceptions only

Failed, wedged on a blocked issue, or overdue. Healthy routines are a count in
the footer and nothing else.

A schedule you can predict is not information. The old list spent its whole
height saying twenty routines would fire on time, and gave the two that had
broken the same weight as the eighteen that were fine.

## Queue age filters

**All / Today / Yesterday / Last week / Old** chips in the queue header, each
carrying the count from the *unfiltered* queue so an empty bucket is
distinguishable from a hidden one. Empty buckets stay visible but disabled, so
the chips never move under the cursor as items age past midnight.

The buckets are calendar days cut at local midnight rather than rolling hours —
an item raised at 9pm last night is yesterday's at 8am today. The Age *grouping*
uses the same buckets, so the filter and the grouping can never disagree about
which pile something is in.

Under an age filter, **Later starts open**: narrowing to "Old" is an explicit
request for that slice, and a rail whose only match is folded away reads as
empty.

See [The Queue → controls](../queue.md#controls).

## Upgrading

```bash
git pull
pnpm install
pnpm build
```

Nothing to migrate. Preferences from the retired classic views are cleared from
`localStorage` on first load.

**If you also upgraded Paperclip, the `pnpm build` above is required, not
optional** — see [Install → after a Paperclip upgrade](../install.md#after-a-paperclip-upgrade-rebuild-plica).

## Known limitations

- **`demoDataUrl` does nothing.** The field is declared in the manifest and the
  host renders it on the settings page, but no code reads it; the fixture is
  always the one shipped with the plugin.
- **Cross-company links do a full page load.** Deliberate, and a workaround for
  a Paperclip core defect: an in-app hop across company prefixes leaves the
  host's sidebar pointing at the previous company.
- **`pnpm test` requires a prior `pnpm build`** on a fresh clone.
